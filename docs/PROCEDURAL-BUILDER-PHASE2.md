Status: **experimental, partial, not deployed**. This extends the draft PR #4 work based on `b06b22c`. The ordinary ElseMesh URL still opens the authored island and its warehouse, computers, roads and vehicles. The new world remains opt-in through `?landscapeBuilder`.

The current release gate and isolated production-build preview procedure are recorded in [PROCEDURAL-BUILDER-RELEASE-GATES.md](PROCEDURAL-BUILDER-RELEASE-GATES.md). The local-only image-guided experiment is excluded from the production artifact; `npm run verify:release-assets` checks this after build.

## Architecture and versioning

The renderer is ElseMesh's WebGPU/WGSL stack. `LandscapeHeight` supplies CPU height and biome queries, and emits matching WGSL for `TerrainGPU`. `ProceduralWorld` streams 256 m chunks, selects three LODs, builds at most two chunks per frame and caps residency at 49. Eviction disposes chunk geometry and vegetation instances. `TerrainData` uses the same edited height outside the authored island. The authored square `|x|,|z| <= 1536` remains protected.

Version 1 remains the finite 2 km starter island with its existing world ID and save behaviour. Version 2 adds `expansion: true` to the canonical spec and composes that starter island with seeded outer islands from `ProceduralHeight`. Entire seeded islands close to the starter rectangle are suppressed to keep the shared seabed continuous at its boundary. The supported world-coordinate envelope is ±90 km, not mathematical infinity. No floating-origin system exists. The reproducible example is [`temperate-2049-expanded.json`](../public/landscapes/temperate-2049-expanded.json).

The v2 world document uses `elsemesh.landscape-world/v1` and contains the canonical generation spec and world ID, generator version, bounded terrain brushes, stable building placement IDs and removal tombstones. Coordinates and edit radius are metres. Edits within the protected island, invalid assets, underwater placements, incompatible versions and excessive records are rejected. Import and save validate before replacing the active document. A changed world identity archives the previous valid document under its old world ID in browser storage; export JSON is needed for a portable backup. Runtime reload after an edit reconstructs CPU terrain, collisions and GPU shader height together. Player position, map discovery, beacons and other game state remain separate, namespaced browser storage; the exported world document does not include them.

## User guide

1. Open `/?landscapeBuilder` locally. Keep the 2,000 × 2,000 m, seed 2049 sample and enable **Version 2**. Select **Save and explore**. The authored home island is still available through **Go home**.
2. Use the existing camera or vehicle controls to leave the starter rectangle. Outer terrain follows the fixed seed. The map and on-screen chunk count show streaming. Return to the warehouse and use its existing entrance and computer room.
3. In the builder, set X/Z outside the protected island. **Apply terrain brush** adds a bounded raise/lower edit. **Place warehouse here** replaces the one active licensed warehouse placement, provided the footprint is dry and within the allowed relief. The building keeps the existing collision and computer-room portal adapter. **Remove placed warehouse** records a tombstone.
4. Export **portable world JSON**, then reload or import it in another browser. Terrain and object edits reconstruct from the saved generation spec. Browser player progress is not part of that JSON.

The current `paths` and `roads` fields define one graded access corridor to the active warehouse entrance. Arbitrary route polylines, branching road networks, traffic, multiple simultaneous warehouse portals and general GLB placement are **not implemented**. Building placement uses the cleared `abandoned-warehouse` GLB and its existing collision adapter; no image-derived asset is silently made placeable.

## 2D-to-3D boundary

`tools/ai-2d-to-3d/build-warehouse.mjs` reads a human-authored dimension and parts specification plus reference-image bytes/hashes. It programmatically emits a real GLB mesh and collision sidecar, loaded by `ImageGuidedWarehouse` in a separate opt-in gallery. The script does not infer dimensions, surfaces or hidden geometry from image pixels. `LandscapeAssets` stores provenance, licence and adapter metadata; its reference fields do not convert photographs into mesh. No Argon, Gemini, Blender MCP or external paid service is called by this builder. The prior candidate demonstration and its limitations are in [`AI-2D-TO-3D-EXPERIMENT.md`](AI-2D-TO-3D-EXPERIMENT.md). Candidate visual fidelity and public placement remain unqualified.

## Qualification method and limits

Automated tests cover v1 compatibility, v2 deterministic reconstruction, boundary continuity, negative coordinates, world edit validation, save/reload, archive-on-identity-change, warehouse collision and CPU/WebGPU shader parity. On 15 October 2026, after completion-gate fixes, `npm test` reported **106 pass, 2 skip, 0 fail**; `npm run test:landscape-gpu` reported **10/10 pass** with maximum CPU/WGSL height error **0.000159654 m** across eight variants, including the largest accepted seed and a low elevation ceiling; `npm run build` passed (324 modules). A test passing in Node or Dawn does not qualify desktop/mobile browser rendering, visual quality or long-distance traversal.

At commit `79b3747`, [Pages workflow run 38754319313](https://github.com/lozknowles/ElseMesh/actions/runs/38754319313) passed its build, full regression command, GPU parity and bundle steps. Its Pages configuration, artifact upload and deploy job were skipped for the pull request. [Controls run 38754319297](https://github.com/lozknowles/ElseMesh/actions/runs/38754319297) passed on Ubuntu/Node 22 and Windows/Node 24. These CI environments do not establish performance or gameplay qualification on physical target GPUs.

In the local Chrome browser at 1280 × 720, `quality=balanced&scale=0.75`, the v2 builder saved world `landscape-v2-f6aa139c`, seed 2049. A scripted free-camera coordinate sweep moved from the warehouse coordinates (4096, 4300) to an outer island (5584, 3456) and back. CPU terrain height at the outer coordinate was **7.219077768 m** above the zero water level; intermediate seabed at (5212, 3667) was **−90 m**. The streamer reached its **49 resident chunk** cap during the outward sweep and later evicted distant chunks on return. These are runtime state observations from a scripted camera, **not** proof of a player or vehicle journey or visual seam quality. The browser's intro overlay remained visible during this sweep; its frame-time samples are excluded from benchmark claims. One exposed JavaScript heap snapshot after the outward sweep was **589,951,617 bytes**. This is neither a GPU-memory reading nor a controlled peak/steady-state comparison.

The browser UI accepted one 30 m radius, +8 m terrain brush at (5584, 3456); the versioned world document contained that edit in local storage after reload, and the reconstructed runtime CPU terrain height changed from **7.219077768 m** to **15.219077768 m**. A later builder click saved a warehouse placement at that coordinate and tombstoned the base warehouse. After reload, the runtime reported the warehouse object present, its structure at (5584, 3456), and the edited terrain height of **15.219077768 m**. The warehouse was not visually inspected after reload. Object removal, portable cross-browser import, the warehouse-to-computer-room journey under v2, and full browser restart persistence are **not yet browser-qualified**. The earlier warehouse/computer journey belongs to the v1 experiment. Browser evidence therefore supports only a partial qualification.

For a matched performance comparison, use the same browser/GPU, viewport, quality/scale, camera path, warm-up and repeated samples at `b06b22c` and the phase-2 commit. Record median and 1% low rendered FPS from frame durations, frame-time percentiles, chunk-generation median/p95, resident chunk count and terrain buffer bytes. **No such matched baseline/treatment benchmark was completed.** Median FPS, 1% low FPS, frame-time comparison, GPU workload, GPU memory and long-distance normal-travel performance are unavailable. `performance.memory` is JavaScript heap only when exposed; total GPU memory is unavailable without a reliable API. The starter v1 versus v2 fixed view does not by itself prove a speedup. Do not describe camera teleportation as normal vehicle traversal.

## Release and rollback

This branch is for draft review. `.github/workflows/deploy.yml` deploys GitHub Pages from `main`; the repository has no separate staging target. A local Vite URL is a preview, not a deployment. Do not merge or deploy before the browser journey, matched performance, save/reload, visual inspection and full CI pass. Roll back an experimental local world by opening the ordinary URL. Export the world JSON before clearing storage. For a later approved production release, retain the previous `main` SHA and revert the merge through the existing Pages workflow if needed.

## Architect gates

**Plan gate:** Cross-component terrain, persistence and renderer changes triggered review. The architect required explicit v2 instead of reinterpreting v1 saves, CPU/WGSL parity, a bounded coordinate domain, stable IDs and transactional imports, honest building adapter limits, matched benchmarks and no production deployment. The implementation follows those boundaries.

**No-progress gate:** Repeated in-app browser telemetry reported a hidden loader but could not read `window.__app`. The architect checked the startup order: App assigns that global before shader precompile and the loader hides only after init completes. The CUA probe likely used an isolated execution realm; this was not proven. The primary stopped treating the absent probe global and unrelated Statsig 403 messages as application failures. Visible UI and a fresh page-context browser run are the next evidence, rather than a speculative startup patch. A `ScannedDebris` fetch warning is handled by that component and is not itself proof of init failure.

**Completion gate:** The architect reproduced four material defects: a raised-site warehouse was graded back to raw underwater height; revisit and resave could retain an obsolete archived world; CPU and WGSL differed when `maxElevation` was below an outer-island peak; and accepted large seeds failed WGSL compilation because salts were signed and unwrapped. It also found malformed world records could throw from cross-record validation. The primary fixed all five, added focused regression cases, reran the full suite, actual GPU parity and build successfully. The architect still classified the release **partial** because normal travel, visible warehouse and computer interaction, portable import/restart, matched performance and GPU memory remain unqualified. The primary accepts that release boundary and is updating only the draft PR.
